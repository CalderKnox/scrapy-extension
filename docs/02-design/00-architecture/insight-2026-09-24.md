## Structure

The package is still a five-layer distribution plane for Scrapy:

```text
L5  Scrapy components   scheduler / dupefilter / pipeline / spider mixin
L4  Strategy layers     MembershipFilter / QueueStrategy / StorageStrategy
L3  Backend ABCs        QueueBackend / SetBackend / StorageBackend
L2  ConnectionManager   registry, leases, retry, circuit breaker
L1  Adapters            redis / mongodb / kafka / rabbitmq / elasticsearch
                        rocketmq / pulsar / sqs / memcached / dynamodb
```

Queue, dedup, and storage resolve independently, so each may use a
different backend. `ConnectionManager` owns construction, lazy connect,
retry, breaker wrapping, and leases. Deferred-ack backends bind settlement
to `_BoundQueueAckToken` (backend incarnation + physical queue).

Approximate current size: 103 source modules; the four remaining
lifecycle god-classes are `BackendScheduler` (~3700),
`ConnectionManager` (~3114), `BackendSpiderMixin` (~3086), and
`BackendDupeFilter` (~2829). The unit suite collects ~8350 tests; a
CI-equivalent non-integration run on this revision passed with coverage
above the 95.0 / 91.0 floors.

## Runtime and data flows

Delivery still has two buckets:

- **Atomic-pop** (Redis, MongoDB, Elasticsearch): `requires_ack=False`.
  Pop removes the item; ack/nack are no-ops.
- **Per-message-ack** (Kafka, RabbitMQ, RocketMQ, SQS, Pulsar):
  `requires_ack=True`. The scheduler carries the token and settles it
  once.

Durable push commits only on a literal `True` receipt. Stateful queue
strategies persist through generation-addressed, manifest-last snapshots;
restore fail-closes on unreadable or resolution-failed storage
(R141-F1). Lifecycle drains use `bounded_drain_wait` on queue close and
dupefilter quiescence (R144-F23).

## Quality attributes

Hardening through R144 already closed generation fencing, breaker probe
deadlines, identity-template colon collisions, key-name `\Z` anchors,
schemeless userinfo redaction, and settings fail-fast for blank Redis /
Kafka identity fields. This pass asked whether those contracts still
hold and whether sibling waits, apply paths, and broker races were left
behind.

## Clean surfaces (this pass)

- Generation lease/retire/publish, breaker single-probe + probe-deadline
  re-open, and `bounded_drain_wait` itself still match R144.
- Queue close drain covers operations *and* replacement settlements;
  snapshot restore still fences resolution failure (R141-F1).
- Redis Lua pop, Mongo poison quarantine, Kafka watermark commit,
  RabbitMQ in-flight clear refusal, Pulsar single-outcome tokens, and
  `_BoundQueueAckToken` incarnation binding remain intact.
- Bundled Redis/Kafka/RabbitMQ/AWS TLS and remote-auth fail-closed
  contracts still hold (guest exact-match and Kafka `group_id` trailing
  newlines are residual P3).
- R141 red-test closures and R141-F20 audit upload are still green;
  extras, classifiers, and the 3.10–3.14 CI matrix still align.
